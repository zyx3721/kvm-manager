# kvm-manager v1.2.0 版本更新日志

**发布日期**: 2026-09-20  
**提交数量**: 19 次提交  
**版本类型**: 企业微信认证功能集成版本

---

## 📋 版本概述

v1.2.0 带来完整的**企业微信扫码登录**能力：认证配置新增「企业微信」提供方，支持**直连企业微信自建应用**与**经由统一认证中心（wecom-auth-center）**两种接入方式，通过 `authMode` 随时切换且两套凭据互不丢失。用户先用账号密码登录，在右上角菜单「绑定企微」弹窗扫码完成账号关联，之后即可在登录页选择企业微信扫码登录。本版本同时把 README 重整为精简主文档（原内容迁移为 `docs/manual.md` 完整手册），并修复 AgentID 字符串形态、审计日志用户为空等多处问题。

---

## ✨ 新增特性

- 认证配置新增「企业微信」提供方，`authMode` 切换直连与统一认证中心两种方式，字段文案与配置步骤引导对齐 itdb-new。
- 企业微信账号绑定模型：`auth_wecom_bindings` 表约束一个用户绑定一个企微账号、一个企微账号只能绑定一个用户，绑定冲突原子拒绝。
- 右上角用户菜单新增「绑定企微 / 解绑企微」入口：绑定在 680×680 弹窗中完成扫码，postMessage 通知主窗口后成功 300ms / 失败 1.5s 自动关窗。
- 登录页选中企业微信后，账号密码表单切换为扫码说明卡片，点击「企业微信扫码登录」按钮经后端取地址后跳转授权页，4 秒兜底复位。
- 新增 `GET /api/auth/wecom/authorize`（取登录地址）、`GET /api/auth/wecom/callback`（直连回调）、`GET /api/auth/wecom/sso/callback`（认证中心票据回调）、`GET /api/auth/wecom/bind-url`、`DELETE /api/auth/wecom/bind` 五个接口。
- 直连回调地址前缀可留空，按用户当前访问地址（`X-Forwarded-Proto` + Host）自动推断。
- 基础配置「安全时效」新增「企业微信扫码有效期」（1-60 分钟，默认 5 分钟），OAuth state 签发时实时读取。
- 企业微信绑定与登录失败写入审计日志（`auth.wecom.bind` / `auth.wecom.unbind` / `auth.wecom.failed`），失败场景可定位系统用户时一并填充用户列与资源列。
- 企业微信 access_token 进程内缓存、到期前 5 分钟刷新，失效（40014/42001）自动清缓存重试一次。
- 右上角用户菜单优先显示用户显示名称（displayName）。

## 🐛 Bug 修复

- 修复历史数据中 AgentID 以字符串数字落库导致 `json.Unmarshal` 到 int 失败、扫码报「应用配置不完整」的问题：保存时归一化为数字，运行时解析兼容字符串形态。
- 修复 `auth.wecom.bind` 审计用户列为空的问题：绑定回调无会话头，改为携带 state 中记录的发起绑定者身份。
- 修复 `auth.wecom.failed` 审计用户列为空的问题：绑定冲突与账号被禁用场景可确定系统用户时，用户列与资源列（`user/<id>`）一并填充。
- 修复二进制部署 Nginx 示例缺失 `/api/events` SSE 事件接口配置的问题，避免前端实时刷新事件被缓冲阻塞。
- 修复用户菜单顺序与绑定弹窗后主窗口绑定状态不同步的问题。
- 修复认证方式卡片在 Windows 下的鼠标光标形态（pointer）。

## 🚀 性能优化

- 企业微信客户端按凭据指纹缓存，配置变更自动重建，避免每次扫码重复获取 access_token。
- 登录页与回调页对授权参数做一次性快照并立即清理地址栏，防止 F5 重复消费已使用的授权码；`pageshow` 处理 bfcache 恢复场景。

## 🔧 重构优化

- 企业微信认证界面结构与交互全面对齐 itdb-new：单一「企业微信」提供方 + 「认证方式」卡片切换 + 「应用配置」分组 + 配置步骤引导卡片。
- 表单悬浮提示改为 label 虚线下划线 + Tooltip（`labelHint`），替代字段下方常显说明文字；详情面板按钮区补充分隔线。
- 显示名称改为只读（跟随提供方默认名称），密码可见按钮始终可点击。
- 会话签发逻辑抽取为共用出口，本地、AD/LDAP、企业微信登录路径统一携带真实企微绑定状态（`wecom_bound`）。
- 数据库迁移合并：未发布的 002-004 三个企微迁移脚本合并为单一 `002_wecom_auth.sql` 最终形态。

## 🔄 API 变更

- 新增免认证接口：`GET /api/auth/wecom/authorize`、`GET /api/auth/wecom/callback`、`GET /api/auth/wecom/sso/callback`。
- 新增需登录接口：`GET /api/auth/wecom/bind-url`（获取绑定跳转地址）、`DELETE /api/auth/wecom/bind`（解绑）。
- `GET /api/settings/auth-providers/{id}` 现支持 `id=wecom`，配置中 `secret`、`ssoAppSecret` 脱敏为 `hasSecret`、`hasSsoAppSecret`，留空时保留已保存值。
- `POST /api/settings/auth-providers/{id}/test` 对企业微信通过 `message` 字段返回测试结果提示。
- `GET /api/auth/providers` 与 `GET /api/auth/me` 响应不变；登录响应新增 `wecom_bound` 字段（企业微信登录为 `true`）。

---

## 📊 数据库变更

- `auth_providers` 表新增 `wecom` 提供方预置行（`002_wecom_auth.sql`）。
- 新增 `auth_login_states` 表：OAuth 登录/绑定 state 一次性存储，`purpose` 区分 login/bind，取出即删防重放。
- 新增 `auth_wecom_bindings` 表：企微账号绑定关系，`user_id` 主键 + `wecom_userid` 唯一约束。
- 权限描述更新：查看/管理认证配置的描述覆盖企业微信认证（`settings.auth.read` / `settings.auth.manage`），内置角色权限集合不变。

## 🔄 升级说明

- 直接重启后端即可，启动时自动执行 `002_wecom_auth.sql` 迁移，无需手动执行 SQL。
- 存量企业微信配置中的字符串数字 AgentID 已完全兼容，无需修正；重新保存一次配置会自动归一化为数字形态。
- 升级后企业微信认证默认关闭，需在「系统配置 → 认证配置 → 企业微信」填写凭据并启用；登录页与右上角菜单随启用状态自动显示。
- 旧版本如已创建 `wecom_center` 提供方数据，迁移会自动合并进 `wecom` 行并切换为统一认证中心模式。
