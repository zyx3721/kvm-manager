## 📋 版本概述

本版本聚焦登录安全、密钥管理健壮性与跨项目配置口径统一：新增登录失败锁定机制（连续密码错误达到阈值后锁定，内置管理员 admin 不受限），锁定次数与锁定时长纳入平台「安全时效」配置；找回密码重置成功后自动解除登录失败锁定；JWT 密钥未显式配置时由「进程内随机、重启全员下线」改为随机生成后持久化到数据库，重启不再影响已登录会话；前端登录态切换为 localStorage 持久存储，实现同一浏览器内新建标签页与重启浏览器自动登录；同时修正 go.mod 依赖标记与会话函数注释。

---

## ✨ 新增特性

- **登录失败锁定**：同一账号连续密码失败达到「安全时效」配置的锁定次数后返回 429 并提示剩余等待分钟数，锁定时长内即使密码正确也会被拒绝，登录成功或锁定窗口过期后重新计数，内置管理员 admin 不受限；仅凭据错误计数，企业微信 OAuth 登录不涉及
- **锁定参数平台化配置**：「系统设置 → 基础配置 → 安全时效」新增「登录失败锁定次数」（3-10 次）与「登录锁定等待时长」（1-10 分钟）两个配置项，后端判定实时读取平台配置，保存时范围校验
- **找回密码联动**：找回密码重置成功后自动解除该账号登录失败锁定（该账号此前的会话吊销能力保持不变），审计 metadata 增加 `login_lock_cleared` 标记
- **审计增强**：登录锁定拒绝写入审计日志
- **浏览器持久登录**：前端登录态由 sessionStorage 切换为 localStorage，同一浏览器新建标签页、重启浏览器均可自动登录；无痕模式与其他浏览器不共享登录态，登录态仅在服务端会话过期（默认 12 小时，401）后失效
- **JWT 密钥持久化**：未设置 `JWT_SECRET` 时随机生成 32 字节密钥并持久化到数据库 `system_secrets` 表，显式配置的环境变量优先；重启不再使全部会话失效，删除数据库才会全员下线

## 🔄 API 变更

- `POST /api/auth/login`：新增 429 锁定响应（达到锁定次数时返回剩余等待分钟数提示）
- `POST /api/auth/password-reset/confirm`：行为增强，重置成功后解除该账号登录失败锁定（会话吊销为既有行为）

## 📊 数据库变更

新增迁移 `004_system_secrets.sql`（`system_secrets` 表，JWT 密钥持久化）与 `005_login_failure_log.sql`（`login_failure_log` 表与索引，登录失败锁定计数）；不改其他表结构，无数据迁移。

## 🔄 升级说明

- 直接替换二进制或更新镜像即可，迁移随启动自动执行，无需手工执行 SQL
- 行为变化提示：登录失败锁定默认开启（5 次锁 2 分钟），可在「安全时效」中调整；浏览器关闭不再清除登录态（localStorage 持久存储），需要退出请使用页面登出；找回密码重置成功后该账号所有已登录设备将被踢下线并解除锁定
- 此前未配置 `JWT_SECRET` 的部署升级后，首次启动会将新生成的密钥持久化到数据库，此后重启不再掉线；如曾依赖「重启清会话」行为请注意
- 旧环境变量 `LOGIN_MAX_FAILURES` / `LOGIN_LOCKOUT_MINUTES` 不再使用（如有配置可移除），锁定参数改在「安全时效」中调整
