# kvm-manager v1.1.0 版本更新日志

**发布日期**: 2026-06-07  
**提交数量**: 5 次提交  
**版本类型**: 功能增强版本

---

## 📋 版本概述

v1.1.0 聚焦告警通知能力增强，新增飞书、企业微信和钉钉自建应用通知渠道，并将外部告警通知的超时、重试和单轮处理批量纳入系统基础配置。同时同步完善通知配置 UI、找回密码发送渠道、告警投递记录、Swagger/OpenAPI 文档和 README 说明。

---

## ✨ 新增特性

- 新增飞书应用通知渠道，支持通过自建应用向用户、邮箱或群聊发送告警、恢复通知和找回密码验证码。
- 新增企业微信应用通知渠道，支持向成员、部门或标签发送告警、恢复通知和找回密码验证码。
- 新增钉钉应用通知渠道，支持通过企业内部应用工作通知发送告警、恢复通知和找回密码验证码。
- 新增告警通知策略配置，支持设置发送超时、最大重试次数、重试基础间隔、重试最大间隔和单轮处理批量。
- 新增飞书富文本和卡片标题模板配置，支持分别设置告警与恢复消息标题。
- 新增飞书卡片标题颜色配置，支持告警与恢复场景分别选择颜色。
- 找回密码流程支持已启用找回密码用途的应用通知渠道。

---

## 🐛 Bug 修复

- 修复重复保存通知配置时敏感配置可能被空值覆盖的问题，默认保留已配置密钥，仅在请求清空配置时清除。
- 修复外部通知失败重试策略固定不可调的问题，改为读取系统基础配置。
- 修正告警模板中虚拟机 IP 和描述为空时的展示值，避免通知内容出现空字段。

---

## 🚀 性能优化

- 告警通知发送超时改为可配置，避免外部通知渠道响应过慢时长时间占用发送流程。
- 告警通知待发送与待重试扫描批量改为可配置，便于根据部署规模调整处理压力。
- 投递失败的指数退避参数改为可配置，支持在可靠性与重试频率之间按环境取舍。

---

## 🔧 重构优化

- 新增应用通知发送实现，封装飞书 tenant access token、企业微信 access token 和钉钉 access token 获取及消息发送流程。
- 将告警通知运行时配置集中从系统基础配置读取，并统一应用到首次发送和重试投递。
- 将数据库初始化迁移收敛到 `001_init.sql`，新部署环境可一次性初始化当前完整表结构。
- 拆分虚拟机告警 metadata 构造逻辑，统一补齐虚拟机名称、IP 和描述等模板变量。

## 🔄 API 变更

- `GET /api/settings/base-config` 返回新增告警通知策略字段。
- `PUT /api/settings/base-config` 支持更新告警通知超时、最大重试次数、重试基础间隔、重试最大间隔和单轮处理批量。
- `GET /api/settings/notifications` 返回新增应用通知渠道及敏感字段配置状态。
- `PUT /api/settings/notifications/{id}` 新增支持 `lark_app`、`wechat_app` 和 `dingtalk_app`。
- `PUT /api/settings/notifications/{id}` 新增 `clearConfig` 字段，用于显式清空已保存配置和敏感信息。
- `POST /api/settings/notifications/{id}/preview` 补充飞书标题和卡片颜色预览字段。

---

## 📊 数据库变更

- `system_settings.base_config` 新增告警通知超时、重试次数、退避间隔和批量处理配置。
- `notification_channels` 初始化数据新增 `lark_app`、`wechat_app` 和 `dingtalk_app`。
- `alert_notification_deliveries` 投递失败重试逻辑改为读取基础配置中的重试策略。
- 初始化迁移脚本整合历史 `002` 至 `022` 迁移内容，新部署环境使用单个初始化脚本创建完整结构。

## 🔄 升级说明

升级前请先备份 PostgreSQL 和 Redis 数据。

如果已有环境已经执行过 `001` 至 `022` 历史迁移，需注意本版本将初始化迁移收敛为单个 `001_init.sql`。已部署环境应保持现有数据库迁移记录和表结构一致，避免在同一数据库中重复按全量初始化脚本执行。

升级后可在系统配置中检查新增的通知策略默认值，并在通知配置页按需启用飞书应用、企业微信应用或钉钉应用通知。应用通知需要配置对应平台的应用凭证和接收对象，请确认外部平台权限已开通消息发送能力。
