# kvm-manager v1.1.3 版本更新日志

**发布日期**: 2026-06-08  
**提交数量**: 1 次提交  
**版本类型**: 修订优化版本

---

## 📋 版本概述

v1.1.3 聚焦 Agent 删除后的运行态缓存一致性和刷新任务噪音治理。删除 Agent 后，后端会更稳妥地清理 Redis 中的宿主机、虚拟机和快照缓存，并通过短期删除标记阻止并发中的旧刷新任务把已删除资源重新写回；宿主机、虚拟机和总览读取链路也会过滤数据库中已不存在的 Agent 残留。定时 fast/deep 刷新在没有任何已登记 Agent 时不再创建空任务，避免任务 / 审计页面持续出现“暂无可同步的 Agent”。前端同步优化了 Agent 保存、同步和删除 toast 反馈。

---

## ✨ 新增特性

- Agent 删除后新增短期 Redis 删除标记，阻止并发刷新任务继续写入已删除 Agent 的运行态缓存。
- 宿主机、虚拟机和总览读取链路新增孤儿运行态缓存过滤与清理能力。
- Agent 保存后的后台同步 toast 改为固定卡片，完成或失败后复用同一卡片展示结果。
- Agent 手动同步和删除操作补充更明确的 toast 反馈。

---

## 🐛 Bug 修复

- 修复删除 Agent 后，后台 fast/full 刷新任务可能把旧宿主机、虚拟机和快照运行态重新写回 Redis 的问题。
- 修复 Agent 已删除但总览或宿主机页仍可能显示运行态残留的问题。
- 修复无 Agent 场景下定时刷新持续创建 `runtime.refresh.fast` 空任务，导致任务列表被“暂无可同步的 Agent”记录刷屏的问题。
- 修复手动同步 Agent 时，如果同步过程中 Agent 被删除，前端可能收到不友好的内部错误提示的问题。

---

## 🚀 性能优化

- 无已登记 Agent 时，定时 fast 刷新和低频 deep 刷新直接跳过，不再创建任务、入队和广播同步事件。
- 读取运行态列表时自动清理孤儿缓存，减少后续页面重复读取无效 Redis 数据。

---

## 🔧 重构优化

- 为 Redis 运行态写入增加写入前后删除态校验，降低 Agent 删除与后台刷新并发导致的数据回写风险。
- 后台全局刷新任务遇到同步期间已删除的 Agent 时按跳过处理，不污染失败统计。
- 统一 Agent 同步类 toast 行为，复用虚拟机任务 toast 的固定展示与完成后自动关闭策略。

## 🔄 API 变更

- 接口路径和响应结构不变。
- `POST /api/agents/{id}/sync` 在同步期间 Agent 被删除时返回 `agent_not_found`，前端显示“Agent 不存在”。
- `/api/hosts`、`/api/vms` 和 `/api/dashboard/summary` 会过滤已无数据库登记的 Agent 运行态残留。

---

## 📊 数据库变更

- 本版本不新增数据库表结构或迁移脚本。
- 定时刷新空任务减少后，`tasks` 表不再持续新增无 Agent 场景下的 `runtime.refresh.fast` 空记录。

---

## 🔄 升级说明

升级前请先备份 PostgreSQL 和 Redis 数据。

升级后，删除 Agent 会在 Redis 中写入 10 分钟短期删除标记，用于覆盖后台旧刷新任务的并发窗口。该标记会自动过期，不需要人工清理。若升级前已经存在已删除 Agent 的运行态残留，访问宿主机、虚拟机或总览页面时后端会自动过滤并清理这些孤儿缓存。

如果当前没有任何已登记 Agent，后端定时 fast 刷新和低频 deep 刷新不会继续创建空任务；用户手动点击右上角全量刷新仍保留明确反馈。
