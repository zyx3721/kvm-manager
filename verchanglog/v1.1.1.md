# kvm-manager v1.1.1 版本更新日志

**发布日期**: 2026-06-08  
**提交数量**: 1 次提交  
**版本类型**: 修订优化版本

---

## 📋 版本概述

v1.1.1 聚焦通知配置和邮件发送体验优化，明确找回密码验证码仅通过邮件媒介发送，并完善 SMTP 超时、TLS/STARTTLS、明文认证兼容和端口输入联动逻辑。同时同步更新通知配置页面文案、Swagger/OpenAPI 文档、README 说明和相关测试。

---

## ✨ 新增特性

- 邮件媒介新增 `allowInsecureAuth` 配置，可在受信任内网或特殊 SMTP 中继场景下允许未加密连接执行明文认证。
- 邮件 SMTP 发送流程新增 8 秒默认超时，并复用系统基础配置中的告警通知发送超时。
- 邮件配置页支持 SMTP 端口联动，输入 `465` 自动启用 TLS/SSL，输入 `587` 自动启用 STARTTLS，同时保留手动取消能力。

---

## 🐛 Bug 修复

- 修复非邮件通知媒介仍可能保存或展示找回密码用途的问题，后端保存和列表返回均限制找回密码只适用于邮件媒介。
- 修复找回密码说明容易误导为会发送到邮件通知收件人列表的问题，验证码现在明确发送到用户账号配置邮箱。
- 修复 SMTP 端口使用数字输入框时鼠标滚轮可能误改端口的问题，改为文本输入并保留端口范围校验。
- 优化 SMTP 错误提示，将底层发送失败统一包装为 `SMTP 发送失败`，便于定位 TLS、STARTTLS、认证或网络超时问题。

---

## 🚀 性能优化

- SMTP 连接、TLS 握手、STARTTLS 升级和消息写入流程统一设置超时，避免邮件服务器异常时长时间阻塞通知发送。

---

## 🔧 重构优化

- 重构 SMTP 发送链路，统一封装普通连接、TLS 连接、STARTTLS 升级、消息写入和错误包装逻辑。
- 前端通知配置保存时统一处理邮件专属找回密码开关，非邮件媒介只保留告警通知和恢复通知用途。
- 后端通知配置清洗逻辑在启用 TLS/STARTTLS 时自动清理明文认证配置，避免互斥配置同时生效。

---

## 📚 文档更新

- 更新 README 通知配置、找回密码、API 文档和版本历史说明。
- 更新 Swagger/OpenAPI 文档，补充邮件媒介 `allowInsecureAuth` 配置和找回密码媒介范围。
- 更新通知配置页文案，说明邮件收件人仅用于告警和恢复通知。

---

## 🔄 API 变更

- `GET /api/settings/notifications` 对非邮件媒介返回 `passwordResetEnabled=false`。
- `PUT /api/settings/notifications/{id}` 仅邮件媒介接受找回密码用途开关，非邮件媒介会强制保存为关闭。
- 邮件通知配置新增可选字段 `allowInsecureAuth`，仅在未启用 TLS/STARTTLS 时生效。
- `POST /api/auth/password-reset/verify` 返回的找回密码媒介范围调整为已启用找回密码用途的邮件媒介。
- `POST /api/auth/password-reset/send-code` 仅通过邮件媒介发送验证码。

---

## 📊 数据库变更

- 本版本不新增数据库表结构或迁移脚本。
- 已有非邮件媒介历史 `passwordResetEnabled` 配置不会作为有效找回密码媒介返回；后续保存时会被归一化为关闭。

---

## 🔄 升级说明

升级前请先备份 PostgreSQL 和 Redis 数据。

升级后建议检查系统配置中的告警通知发送超时，并在通知配置页确认邮件媒介的 TLS/SSL、STARTTLS 或明文认证策略。对于 QQ 邮箱等公网 SMTP 服务，通常应使用 `465 + TLS/SSL` 或 `587 + STARTTLS`；`allowInsecureAuth` 仅适合受信任内网 SMTP 中继或明确要求明文认证的兼容场景。

找回密码验证码仅会发送到用户账号配置邮箱，不再通过 Webhook、飞书、企业微信、钉钉或应用通知发送。
